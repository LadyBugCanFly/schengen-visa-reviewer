## 1. Result at a glance

Use a practical grade instead of a pseudo-precise approval score:

- **A · 🟢 Ready for final checks:** no unresolved Critical or High finding.
- **B · 🟡 Fix a few items first:** targeted material work remains.
- **C · 🟠 Do not submit unchanged:** important contradictions or evidence gaps remain.
- **D · 🔴 Rebuild key parts:** a Critical defect fundamentally undermines the application.
- **Not rated · ⚪:** important documents are unavailable or unreadable.

Say that this measures document readiness, not approval probability. Show counts for **Must fix**, **Recommended improvements**, and **Optional polish**, followed by a direct answer to “Can I submit this version?”

### Four-part profile

The official checklist is a submission gate. The profile below then answers four user goals: is the trip real and executable, is the money sufficient and explainable, is timely return supported, and do all documents agree? Draw a radar chart when supported, but always include this fallback:

| Check | Result | One-sentence explanation |
|---|---|---|
| Trip purpose and factual executability | weak / needs work / good / strong / unable to assess | |
| Financial capacity and explainability | weak / needs work / good / strong / unable to assess | |
| Return plan is supported | weak / needs work / good / strong / unable to assess | |
| Documents agree and look reliable | weak / needs work / good / strong / unable to assess | |

Prefer qualitative labels. If supporting numbers are shown, round to the nearest 5 and explain the main deduction. Do not average them into an apparent visa-success percentage.

## 2. Your action list

Before the action list, show **Required-document check** near the front of the report:

- identify the responsible country, purpose, submission location, and checklist source with access date;
- state `Complete in supplied documents`, `Items missing or incomplete`, or `Provisional — official checklist not verified`;
- show counts for Provided, Partly provided, Missing, Unreadable, and Not applicable;
- list every missing or partly provided item first, with the document that was expected and the exact action;
- provide the full item-by-item table when useful, but collapse routine provided items into categories for phone readability.

Use this compact structure:

| Official checklist item | Status | What was supplied | What to do |
|---|---|---|---|
| | ✅ Provided / ⚠️ Partial / ❌ Missing / ❓ Unreadable / — Not applicable | | |

Put each action here once; do not repeat it later.

- **🔴 Must fix before submission:** Critical and High findings. If none, say so.
- **🟡 Recommended improvements:** Medium findings.
- **🔵 Optional polish:** Low-impact presentation improvements.

## 3. Why each item was flagged

Use phone-friendly issue cards, not a wide findings table. Never expose codes such as C1/M2 or labels such as OFFICIAL/DERIVED/EXPERIENCE/HYPOTHESIS.

### 🟡 Recommended improvement: short title

- **What I found:** observable fact and affected documents.
- **Why it matters:** plain-language consequence without guessing the officer's motive.
- **What to do:** specific, truthful, safe action.
- **Basis:** Official checklist / Document comparison / Practical reminder.

## 4. Checks that passed

List concrete strengths so users know which evidence does not need rebuilding.

## 5. Dates, transport, accommodation, and insurance

Use a compact table only when it helps comparison. Status words: ✅ Matches, ⚠️ Needs explanation, ❌ Conflict or gap, ❓ Unable to verify. Emphasize exceptions and collapse repetitive matching rows.

Add a **Destination and transport fact-check** subsection when an itinerary is supplied. Show only meaningful exceptions and a compact verification summary. For every dynamic claim record the official source and access date. Use: ✅ verified, ◐ partly verified or not yet published, ⚠️ needs correction, ❓ unable to verify.

## 6. Salary and trip funds

Explain whether statement periods, salary dates, payslips, employer pay, payer, trip costs, balance, and unusual credits reconcile. Never reproduce full account numbers or unrelated transactions.
